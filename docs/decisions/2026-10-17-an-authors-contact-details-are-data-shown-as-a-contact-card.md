# An author's contact details are data, shown as a contact card

*Recorded 17 October 2026 from ARCHITECTURE.md (#756); decided with #19, #25 and #113.*

`Author.contact` holds what RFCXML's `<author>` publishes: `<organization>` and an `<address>` with its `<postal>`, phone, fax, emails and URI. `PostalAddress` keeps whichever of the schema's two forms the author chose: a field per element, a building (`<extaddr>`) apart from a street and a district (`<cityarea>`) apart from a city, or the author's own `<postalLine>`s, and the serializer writes the same form back. The URI is kept as written, so one `URL` cannot read is shown as text rather than lost. The `ascii` transliterations beside these are not kept: the reader shows the document's own script, and the schema makes them optional. `contact` is nil for every author a legacy header or the RFC index names, since nothing is looked up or inferred. Prep's "Authors' Addresses" section is built from the same elements, and a Contributors section from `<contact>`, which has the same content. Those were read as unknown containers, an aside for each level of `<author><address><postal>`, which the schema rejects on a round trip, and as inline names run together, the rest dropped. Both now read as one paragraph per person, a detail per line, with email and web addresses as links, and an organization that is its own entry's name is not repeated beneath it. The parser's fallback for an unknown container, which sets several blocks apart as an aside of its own, splices an aside inside that one rather than nesting it. The header shows them as a contact card: each author is a chip, and one that publishes anything beyond its name opens Apple's `CNContactViewController` on an unsaved contact that `AuthorCard` (RFCReaderKit) builds from exactly these fields, the author's own postal lines kept as written and a sorting code after the city, where France writes a CEDEX, since Contacts has no field for it (#19). The chip's monogram is white initials on a tint picked by an FNV-1a hash of the name, and text drawn on a color the code picks is held to a calculated contrast ratio: WCAG 2.x relative luminance and contrast, computed by `SRGBColor` (RFCReaderKit), against the 4.5:1 Apple's Human Interface Guidelines ask of text at standard sizes, since initials are small bold text and the 3:1 for large text does not apply. The system colors cannot meet it with white — yellow measures 1.5:1, mint 2.1:1, only indigo passes — and resolve differently by appearance and platform, so `AuthorMonogram.palette` is fixed sRGB: each system hue darkened in linear light until white clears 4.5:1, which keeps the hue and, the circle being opaque, the same contrast in light and dark appearance. Switching the initials to black on the light tints was the alternative, and passes too, but would draw seven of the eight chips differently from the eighth. The inspector's Info pane (#25) lists the authors with the same chips.

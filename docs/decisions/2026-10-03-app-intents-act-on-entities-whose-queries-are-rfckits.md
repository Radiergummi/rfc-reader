# App Intents act on entities whose queries are RFCKit's

*Decided and built October 2026 (issue #192).* Shortcuts, Siri and Spotlight act on three App Intents entities: `RFCEntity`, `SectionEntity` and `RegistryEntryEntity`. Open RFC takes an RFC entity rather than a number, so a phrase can name the RFC; Open Section, Look Up Identifier and Find Requirements are new. What each query finds is a pure function in RFCKit: `DocumentLookup` for RFCs (a number in any spelling names that RFC alone, a series its members, anything else is searched as the sidebar searches it), `SectionLookup` and `SectionIdentifier` for sections, `Requirements.within` for a section's requirements, and `RegistryLookup` for identifiers. The issue allowed RFCReaderKit or RFCKit; RFCKit, because the queries read only its types, and RFCReaderKit builds only with an Apple SDK, so these are tested on Linux as well. The App target holds the conformances alone.

A section is identified across documents as `rfc9110#section-4.2`, the file stem and the anchor, so Shortcuts can hand one back without its document. Listing a document's sections means loading the document, which an intent does as opening it does: from memory, the cache or an installed pack, and otherwise from the network. Offline without it, the intent fails saying the document isn't available offline, rather than listing nothing, which would read as a document without sections.

Find Requirements returns text, one line per requirement with its section's number (`Requirement.line`), so a shortcut can pass it on; its result's button shows the Requirements tab instead. That tab is the reader's, and the intent has no scene, so it routes the link as any link from outside is routed and leaves an `InspectorRequest` on `LibraryModel`, which the reader showing that document takes once its panel can open: on macOS the panel refuses to open over a document still loading.

Spotlight's items (#178) stay as they were, with their domain, expiry, batches and client state, and each carries its RFC's entity through `CSSearchableItem.associateAppEntity`. That makes a Spotlight result the RFC that Shortcuts and Siri act on, as #178 agreed. Donating through `CSSearchableIndex.indexAppEntities` instead, as the design comment proposed, would have lost the items' expiry, which is what lets an RFC that leaves the index leave Spotlight, and the batches the client state is written with. The client state includes a format marker, so the items indexed before are indexed again once, on the first launch after the update.

"Open the section that defines Retry-After" waits for a corpus-wide index of defined terms (#397); the intent over it is #730.

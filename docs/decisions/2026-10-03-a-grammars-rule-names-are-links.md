# A grammar's rule names are links

*Decided October 2026 (issue #185).* An ABNF block, one typed `abnf` or `abnf9110` by its author or by the legacy parser's recognizer, is rendered as *linked text*: the block's own characters, set exactly as before, with a rule's definition marked as an anchor and each use of a rule name made a link. `Rendition.linked(LinkedText)` carries the ranges, and nothing visual. Find, selection, copy, VoiceOver and the block's layout are what they are for an unlinked block. Since nothing drawn changes, a grammar has no presentation to switch: it is plain, with no figure menu and no figure item over it (which on iOS would take a press from its links), and it is linked whatever the reader prefers for figures.

**The anchors.** A rule's definition is the anchor `abnf-<name>`, lowercased because RFC 5234 compares rule names without case (`#abnf-field-value`). It is a stable string like every other anchor, so it can be deep-linked and is in the `AnchorIndex`, but it is never a section's, so section tracking and the contents ignore it. The first definition of a name is its anchor. A later one, an error the legacy series makes, is not. An `=/` rule adds to a rule defined before it, and is a use of its name; one that extends another document's rule stays plain.

**The grammar is collected before the build.** A document spreads its grammar over sections, as RFC 9110 does over every section that defines a field, so a use in one block links to a definition in another. The builder classifies every verbatim block and collects the rules of those typed ABNF into a `DocumentGrammar` before it emits anything. This is the per-document pass the artwork design reserved. It asks only for a block's stated type (`ArtworkClassifier.statedType`), since no recognizer finds a grammar, and leaves out a block the reader shows other than as written, folded per RFC 8792 or set with tabs: its rules could not be anchored in its own text, and a link to an anchor never set would go nowhere. A presentation reads it from its `RenderContext`, and the built document keeps it for a rule link's preview.

**Where a use links.** It links to the document's own definition, or, for one of RFC 5234's sixteen core rules the document does not define itself, to RFC 5234 Appendix B.1. A name defined nowhere in the document, such as one RFC 9112 uses from RFC 9110, stays plain until rules can be resolved across documents, which needs a `rules` table in the index pack once the app reads packs (#36).

**A link is a cross reference.** Each use carries `.rfcReference` with the link's `CrossReference`, so the click, the macOS hover and force click, and the iOS long press work as for any reference. It is never a chip, which would change the block's width. `SelectionText` copies a reference inside a verbatim block as the block's text, not its label. The hover card of a rule link shows the rule's definition, its lines as the block sets them, in place of the heading an anchor's card shows.

**Recognizing and parsing part.** `ABNF.parse` reports the UTF-16 range of every definition and use in the text as given. A name defined twice, and a count running into hex digits (`4c0ffee`), parse: a block its author typed `abnf` is linked whatever its mistakes. Only `ABNF.recognizes` refuses them, so what the legacy parser types as ABNF does not change. `|` alternation, as RFC 822 and RFC 2616 write it, is still not ABNF: accepting it would change what thousands of legacy blocks are typed as, and needs its own corpus-measured change.

**The collected grammar.** A document with a grammar can be saved as one `.abnf` file (`GrammarExport`, offered beside PDF): every grammar block in document order, without the indentation the document set it at, each headed by its section in a comment. A closing comment names the core rules used, pointing to RFC 5234 Appendix B.1 rather than copying their definitions, which are that RFC's text, and the names used but defined nowhere.

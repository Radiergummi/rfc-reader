# Overrides are RFC 5261 patches on the converter's output

*Decided September 2026, built October 2026 (issue #197; round trip #683).* A correction to one legacy document is a patch in the format of RFC 5261, An XML Patch Operations Framework Utilizing XPath Selectors, applied by `corpus-build convert` after conversion, rather than a snapshot of the whole converted document or a script that makes one. A snapshot never breaks, but it never takes a parser improvement either, and it commits the document's entire text, which is RFC text whose licensing is an open question; a patch holds only selectors and operations, and RFC text only where it restores the minimal text of content the converter misclassified. The scripts that regenerated snapshots were Python in a Swift repository, guarding a regeneration that had to be remembered. The RFC texts are frozen; what changes is the converter's output, so an override says what to correct in that output, and the many one-document corrections the 8,457 legacy RFCs will need share one mechanism.

`XMLPatch` lives in `RFCCorpusKit`, not RFCKit, because the app never applies a patch. It is Foundation's `XMLDocument`, which evaluates XPath 1.0 and edits nodes on Linux (libxml2) as on macOS (NSXML). The alternatives were rejected: XSLT through Foundation (`XMLDocument.object(byApplyingXSLTString:)` is unavailable in swift-corelibs-foundation, so it does not compile on Linux, where `corpus-build` is built and tested); XSLT through XalanSwift (a macOS and iOS xcframework with no Linux slice, and 41 MB of vendored C++); `xsltproc` as a subprocess (another tool for CI and contributors to install, for a job Foundation does); and operations of our own on the `RFCDocument` model, which would throw away RFC 5261 and XPath, the reason for the choice. Two deviations from the RFC: selectors are full XPath 1.0, so an operation can select by content, which is frozen where structure is not; and there is no `ws`, since the patched document is written again.

Validation is strict, because a patch that silently does less is worse than one that fails. Every selector must match exactly one node, as the RFC requires; the node must suit its operation; an unknown operation or attribute is an error, so `postion=` does not quietly append. Failures are values naming the patch, the operation and the reason. Within a document the first failure stops its patch, since later operations would see a tree its author did not intend; across a run, every failure is collected and logged, the document writes no output and an earlier run's is removed, so the manifest never takes an unpatched document for a success, and the run exits non-zero at its end.

The patched document is parsed with `RFCXMLParser` and written again with the serializer, rather than published as `XMLDocument` writes it: that output differed from its input before any patch (32,214 characters became 29,565 by default, 32,234 preserving whitespace), and differently on each XML library. Writing it again is canonical only if the serializer's output is a fixed point of parsing and writing, which it was not: 2,717 of 8,457 documents changed on a second write. #683 made it one, all but 7 documents whose cause is a parser bug of its own (#686), and every conversion now checks it, as a warning in a corpus run and as a test over every fixture in `make check`. Writing again can also drop what a patch added and the model cannot hold, so the patched tree's words and the written XML's must be the same, or the document fails, naming where they part. And writing again can undo the whole patch, where it changed only what the writer derives, so output equal to the converter's own to the byte fails too.

`make corpus-overrides-check` converts only the patched documents, with the index, on every pull request in CI and before every corpus conversion, so a parser change that breaks a patch fails its own pull request, and a broken patch stops in seconds rather than after twenty minutes. Its inputs are file targets fetched when they are missing, since what it takes from the index was fixed when each document was published; a corpus run's fetch downloads a fresh index over it, so it sees every RFC published since. RFC 1142 stays a snapshot, the one exception: its correction rejoins words split by form feeds in the plain text, before conversion, which a patch on the output cannot do, and a text-level stage is not worth building for one document.
